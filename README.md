# AIContentMaker — нейро-контентмейкер для Telegram

AIContentMaker — это Telegram-бот, который снимает стиль с существующего канала и помогает владельцу генерировать посты и контент-планы на неделю в этом же стиле.

---

## Возможности

- Снять стиль письма с любого открытого канала по ссылке или @username.
- Сохранить стиль под удобным именем и закрепить за пользователем.
- Генерировать одиночные посты по краткому брифу.
- Генерировать и сохранять контент-план на неделю (1–3 поста в день).
- Хранить планы в базе и показывать текущий план по запросу.
- Отправлять ближайший запланированный пост автоматически в привязанный для этого канал.

---

## Архитектура

Проект состоит из двух частей:

- **Backend** (FastAPI + SQLModel) — REST API, хранение стилей и планов, генерация постов и планов.
- **Telegram-бот** (aiogram 3) — пользовательский интерфейс, сценарии диалога, команды и кнопки.

Основные компоненты:

- `app/` — FastAPI-приложение:
  - `app/api/v1/routes.py` — все основные эндпоинты (`/v1/generate`, `/v1/plan/*`, `/v1/user/*`, `/v1/autopost/next/...`).
  - `app/db/models.py` — модели `User`, `ContentPlan`, `PlanItem` (SQLModel).
  - `app/db/session.py` — session factory.
  - `app/services/plan_generator.py` — генерация недельного плана.
  - `app/services/post_generator.py` — генерация текста постов.
  - `app/services/style_store.py` — загрузка/сохранение стиля на диск.
  - `app/services/telegram_sender.py` — отправка сообщений через Telegram Bot API.

- `bot/` — Telegram-бот:
  - `bot/main.py` — точка входа, создание Bot и Dispatcher, регистрация роутеров и команд.
  - `bot/config.py` — настройки (`BOT_TOKEN`, `API_BASE_URL`).
  - `bot/handlers/start.py` — приветствие и главное меню.
  - `bot/handlers/connect.py` — подключение канала и снятие/именование стиля.
  - `bot/handlers/post.py` — сценарий генерации одиночного поста и `/autopost_demo`.
  - `bot/handlers/plan.py` — сценарий планирования недели и `/plan_status`.
  - `bot/handlers/flow.py` — обработка inline-кнопок «следующий шаг».
  - `bot/services/api_client.py` — клиент для обращения к backend API.
  - `bot/keyboards/main_menu.py` — главное меню (reply-клавиатура).
  - `bot/keyboards/flow.py` — inline-клавиатуры «что дальше».

## Установка и запуск

### 1. Клонирование и зависимости

```bash
git clone <repo-url> ai-content-maker
cd ai-content-maker
python -m venv venv
source venv/bin/activate  # или venv\Scripts\activate на Windows
pip install -r requirements.txt
```

#### 2. Переменные окружения

Создай `.env` в корне проекта (или в нужных модулях), минимум:

```bash
TELEGRAM_BOT_TOKEN=<твой_бот_токен_из_BotFather>
OPENAI_API_KEY=<твой_openai_api_key>
API_BASE_URL=http://127.0.0.1:8000
```

`API_BASE_URL` — адрес backend-сервиса (по умолчанию локальный Uvicorn).

### 3. Миграция/инициализация БД

База хранится в `neuro_content.db` (SQLite через SQLModel).  
Таблицы создаются из моделей `User`, `ContentPlan`, `PlanItem` при старте приложения (см. `app/db/models.py` и инициализацию в `app/main.py`).

Если требуется ручная миграция, добавь вызов `SQLModel.metadata.create_all(engine)` в старте приложения.

### Запуск

- **Backend (FastAPI)**:

```bash
uvicorn app.main:app --reload
```

По умолчанию поднимется на `http://127.0.0.1:8000`.

Основные эндпоинты:

- `POST /v1/generate` — одиночный пост.
- `POST /v1/generate-from-channel` — снять стиль с канала и сразу сгенерировать пост.
- `POST /v1/plan/generate` — сгенерировать черновой план на неделю.
- `POST /v1/plan/confirm` — сохранить план в БД.
- `GET /v1/plan/current/{user_telegram_id}` — получить текущий план пользователя.
- `GET /v1/user/{telegram_id}` — получить текущий стиль пользователя.
- `POST /v1/user/set-style` — установить активный стиль.
- `POST /v1/autopost/next/{telegram_id}` — сгенерировать и отправить ближайший запланированный пост.

- **Telegram-бот**:

```bash
python -m bot.main
```

В `bot/main.py`:  
создаётся Bot с `parse_mode=HTML`,  
регистрируются роутеры:  
`start.router`  
`connect.router`  
`post.router`  
`plan.router`  
`flow.router`  
вызывается `set_bot_commands(bot)` для регистрации команд в меню.

## Сценарий использования (из Telegram)

### Привязка канала

1. Добавьте бота в администраторы канала с правом публиковать посты.
2. В самом канале отправьте `/link_channel` — бот запомнит канал.
3. В личке с ботом запустите `/connect_channel`, выберите стиль и подтвердите его название.
4. Создайте и утвердите план постов через `/plan_week`.

### 1. Старт

1. Открыть чат с ботом.  
2. Нажать кнопку Start или отправить `/start`.  
3. Бот расскажет, что умеет, и предложит начать с `/connect_channel`.

### 2. Подключить канал и снять стиль

1. Команда: `/connect_channel`.  
2. Диалог:  
   - Бот просит ссылку или @username канала (например, `https://t.me/your_channel` или `@your_channel`).  
   - Пользователь отправляет username.  
   - Бот «снимает стиль» (через `POST /v1/generate-from-channel`) и предлагает имя стиля, например `your_channel`.  
   - Пользователь либо оставляет предложенное имя, либо вводит своё (например, `edler_auto`).  
   - Бот переименовывает стиль при необходимости (`/v1/styles/rename`), сохраняет стиль за пользователем (`/v1/user/set-style`), показывает главное меню и inline-кнопки «что дальше».  

После этого у пользователя установлен `active_style_name` в таблице `user`, и все дальнейшие команды могут использовать этот стиль.

### 3. Сгенерировать одиночный пост

1. Команда: `/post`.  
2. Диалог:  
   - Бот проверяет `active_style_name` через `/v1/user/{telegram_id}`.  
   - Если стиль не найден — просит сначала пройти `/connect_channel`.  
   - Если стиль есть — просит прислать бриф в свободной форме.  
   - Пользователь описывает тему/цель/аудиторию одним сообщением.  
   - Бот вызывает `generate_post_api → POST /v1/generate`, получает сгенерированный текст, показывает черновик поста.


### 4. Сгенерировать план на неделю

1. Команда: `/plan_week`.  
2. Диалог:  
   - Бот проверяет, есть ли активный стиль:  
     если нет — просит пройти `/connect_channel`.  
   - Бот проверяет, есть ли уже активный план (`GET /v1/plan/current/{user_telegram_id}`):  
     если есть — честно предупреждает, что новый план заменит текущий (но старый остаётся в истории).  
   - Вопросы по параметрам плана:  
     дата начала (ГГГГ‑ММ‑ДД),  
     время первого поста (ЧЧ:ММ),  
     цель недели (текст),  
     количество постов в день (кнопки: 1 / 2 / 3).  
   - Бот вызывает `POST /v1/plan/generate` и показывает черновой план на неделю.  
   - Пользователь выбирает:  
     «Одобрить план» — бот вызывает `POST /v1/plan/confirm` и сохраняет план в БД;  
     «Сгенерировать заново» — бот запрашивает новый вариант плана с теми же параметрами;  
     «Отменить» — ничего не сохраняется.  
   - При подтверждении плана бот показывает резюме:  
     `plan_id`,  
     дата старта,  
     количество постов,  
     примерное число постов в день,  
     и предлагает следующие шаги (`/plan_status`, `/autopost_demo`).

### 5. Посмотреть текущий план

1. Команда: `/plan_status`.  
2. Бот делает `GET /v1/plan/current/{user_telegram_id}`,  
   если план есть — показывает его в компактном текстовом виде:  
   стиль,  
   цель и аудитория,  
   список постов по датам и времени.

### 6. Отправить ближайший пост по плану (демо)

1. Команда: `/autopost_demo`.  
2. Бот:  
   вызывает `autopost_next_api → POST /v1/autopost/next/{telegram_id}`.  
3. Backend:  
   находит пользователя по `telegram_id`,  
   берёт последний план,  
   находит первый `PlanItem` со статусом `"planned"`,  
   генерирует текст поста через `generate_post`,  
   отправляет пост напрямую в личку пользователю (`send_telegram_message`),  
   обновляет `status="sent"`, сохраняет `generated_post` и `sent_at`.  
4. Бот подтверждает в чате: показывает `plan_id` и `item_id`.

### Автопостинг по расписанию

После генерации и подтверждения контент‑плана бот:

- сохраняет для каждого поста дату и время отправки (`scheduled_at`);
- раз в минуту фоновой воркер (`autopost_worker.py`) опрашивает API;
- API выбирает ближайший пост, у которого время уже наступило, и отправляет его в привязанный канал.

Требования для автопостинга:

1. Бот добавлен в администраторы канала с правом публиковать посты.
2. В самом канале один раз отправлена команда `/link_channel`.
3. В личке с ботом создан и подтверждён план (`/plan_week`).
4. Для пользователя включён флаг `autopost_enabled` (сейчас включается автоматически при подтверждении плана).

## Хранение данных

База `neuro_content.db` (SQLite) содержит как минимум три таблицы:

- **user (User)**:
  - `id`
  - `telegram_id` (уникальный)
  - `active_style_name` — имя текущего стиля пользователя.

- **contentplan (ContentPlan)**:
  - `id`
  - `user_id` (FK → `user.id`)
  - `style_name`
  - `start_date`
  - `goal`
  - `audience`
  - `created_at`

- **planitem (PlanItem)**:
  - `id`
  - `plan_id` (FK → `contentplan.id`)
  - `day_index`
  - `date`
  - `time`
  - `post_type`
  - `topic`
  - `notes`
  - `status` (planned / generated / sent)
  - `generated_post` (текст отправленного поста, если уже сгенерирован)
  - `sent_at` (время отправки).

Стиль (тон, словарь, форматы постов) хранится на диске (например, в JSON-файлах) и подгружается через `style_store`.

## Команды бота

Рекомендуемый список команд (настраивается через BotFather и/или `set_my_commands`):

- `/start` — Запустить бота  
- `/connect_channel` — Снять стиль с канала  
- `/post` — Сгенерировать одиночный пост  
- `/plan_week` — Сделать план на неделю  
- `/plan_status` — Показать сохранённый план  
- `/autopost_demo` — Отправить пост по плану (демо)
- `plan_edit_time` — изменить время постов

## Ограничения и TODO

- Генерация текста постов использует OpenAI API. В некоторых регионах (например, РФ) доступ к API может быть ограничен, понадобится VPN или прокси. В случае 403 (`unsupported_country_region_territory`) автопостинг не сможет сгенерировать текст "на лету". Можно использовать другие API, работающие на территории региона.
  
- Нет UI для управления несколькими стилями на пользователя (используется один `active_style_name`).  
- План генерируется на фиксированный период (неделя); расширение до месячного/динамического плана возможно, но не реализовано.

## Возможные направления развития

Проект задуман как основа для продукта, который можно расширять под задачи заказчика. Ниже — идеи, которые уже заложены архитектурой, но пока не реализованы.

### 1. Ручная корректировка постов

Идея: после автогенерации поста пользователь может "договоредактировать" его простым запросом.

Пример сценария:

1. Бот показывает сгенерированный текст поста.
2. Пользователь отвечает боту текстом: "сделай тон более строгим и убери смайлики".
3. Бот вызывает модель переписывания и обновляет `generated_post` в плане.
4. В автопостинге уже используется скорректированный текст.

Технически это может быть реализовано как:
- отдельный эндпоинт `/v1/plan/adjust-post` с `plan_id`, `item_id` и `instruction`;
- отдельное состояние в боте, где пользователь редактирует текущий пост.

### 2. Веб‑интерфейс поверх текущего API

Текущий backend уже оформлен как REST API (FastAPI), поэтому поверх него можно сделать:

- Веб‑панель для маркетологов: создание стилей, генерация планов, ручное редактирование постов.
- Просмотр истории отправленных постов, статусы (planned / generated / sent).
- Управление автопостингом (включение/выключение `autopost_enabled`, выбор каналов/проектов).

Варианты реализации:
- Лёгкий фронтенд на React/Vue/Next.js, который разговаривает с `/v1/...` эндпоинтами.
- Авторизация по токену/логину, чтобы один backend обслуживал несколько клиентов.

### 3. Дополнительные функции, которые можно добавить

- **Аналитика по постам.** Хранить статистику (просмотры, реакцию) и подсвечивать, какие темы и форматы работают лучше всего.
- **Умные подсказки по темам.** Генерация идей для будущих постов на основе истории канала и предыдущих планов.
- **A/B‑тесты заголовков.** Для одного поста генерировать 2–3 варианта заголовка и случайно выбирать, а затем сравнивать результаты.
- **Мультиплатформенность.** Расширить отправку не только на Telegram, но и, например, на VK/Instagram/другие платформы через отдельные адаптеры.
- **Импорт/экспорт стиля.** Возможность выгрузить/загрузить стиль в JSON, чтобы переносить стили между проектами.
- **Роли и доступы.** Для веб‑версии — разграничение прав: копирайтер редактирует тексты, маркетолог утверждает план, владелец включает автопостинг.
- **Локальные/офлайн модели.** Для обхода ограничений OpenAI можно добавить поддержку локальных LLM (через Ollama/LM Studio и т.п.) вместо или в дополнение к OpenAI.

## Как использовать этот репозиторий

Для демо/презентации:  
- поднять backend и бота локально;  
- показать полный путь: `/connect_channel → /post → /plan_week → /plan_status → /autopost_demo`.

Для дальнейшей разработки:  
- заменить/расширить логику генерации контента;  
- добавить реальный автопостинг в каналы;  
- сделать веб-интерфейс для управления стилями и планами.
